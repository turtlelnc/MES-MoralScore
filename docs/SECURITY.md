# 安全与隐私设计（MES-MoralScore v0.1.0-rc1）

本系统处理未成年人信息。安全目标：**最小化采集、最小权限、服务端强制校验、全程可追溯、对外默认去标识化**。本文描述已实现的机制、部署方必须完成的配置，以及当前版本的已知限制。

## 1. 认证与会话

- 密码使用 `scrypt`（随机 16 字节盐，64 字节派生密钥）哈希存储；只保存哈希与盐，不保存明文。
- 密码策略：≥10 位、必须同时包含字母与数字、不能包含账号名、拒绝常见弱口令；管理员重置密码后 `must_change_password=1`，界面提示修改。
- 会话：随机 32 字节 token 存于服务端 `sessions` 表，客户端使用 `mse_session` Cookie：`HttpOnly`、`SameSite=Lax`、生产 HTTPS 下 `Secure`、默认 7 天过期；过期会话在登录时机会性清理。
- 改密后吊销该用户其他会话，仅保留当前会话。
- 登录失败按 `IP + 账号` 限流（默认 10 分钟内 8 次），超限返回 429 与 `Retry-After`；登录成功/失败均写审计日志。
- 所有非 GET 的 API 请求进行同源写入校验（Origin 与 Host/`APP_ORIGIN` 比对），配合 `SameSite=Lax` 缓解 CSRF。

## 2. 授权与数据范围（防 IDOR）

- 三类固定角色：`SYSTEM_ADMIN`、`MORAL_AFFAIRS`、`DUTY_TEACHER`，无第四类平级管理角色。
- 接口在服务端依次校验：登录 → 角色 → 数据范围。值日老师只能访问 `user_scopes` 授权的年级/班级；管理员与德育处为全校范围。
- 所有按学生/班级/记录/申诉/分享的读写都通过 `ctx.scope` 校验；越权返回 403，不存在返回 404，且不泄露其他班级学生姓名。
- 权限不仅在前端隐藏：所有敏感动作（规则发布、复核、冲正、申诉裁决、备份、导入、账号管理）都在服务端路由上做角色校验。
- 值日老师不能修改已发布规则、不能裁决申诉（`decideAppeals` 仅德育处）、不能管理账号与备份。

## 3. 积分账本不可篡改

- `EFFECTIVE` 状态的积分记录在数据库层由触发器禁止 `UPDATE`/`DELETE`；`PENDING_REVIEW` 记录只允许复核状态流转。
- 撤销/更正通过追加 `REVERSAL` / `CORRECTION` 记录实现，保留原记录、操作者、原因、关联记录与时间；同一记录只允许一条生效冲正（唯一索引）。
- 数据库层禁止修改/删除审计日志与申诉裁决记录（触发器）。
- 规则版本在 `APPROVED`/`PUBLISHED`/`ARCHIVED` 后禁止修改内容；发布后生效时间不可修改；修改必须创建新版本。
- 记录写入时保存规则快照，规则改版不改变历史记录解释。

## 4. 输入与输出安全

- 所有写接口使用 Zod 在服务端校验类型、长度、枚举与业务约束；错误返回中文提示。
- SQL 全部使用参数化查询，无字符串拼接 SQL 值；LIKE 查询转义 `%`/`_`/`\`。
- CSV 导出对以 `= + - @` 开头的单元格前置单引号，防止公式注入；文件名净化。
- 前端 React 默认转义输出；不使用 `dangerouslySetInnerHTML`；CSP 限制 `script-src 'self'`、`object-src 'none'`、`frame-ancestors 'none'`。
- 安全响应头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy`、`Permissions-Policy`，生产 HTTPS 加 HSTS。
- JSON 请求体限制 2 MB；错误响应不返回堆栈、SQL 或内部路径。

## 5. 证据文件

- 仅允许 PNG/JPG/WebP/PDF，按文件头魔数校验（不信任 Content-Type），单文件默认 ≤8 MB、每条记录最多 5 个证据。
- 随机 UUID 文件名，保存在 `DATA_DIR/evidence`（`0600`），**不在**公开静态目录；下载必须登录且通过学生/班级数据范围校验，响应 `nosniff` 与私有缓存头。
- 禁止执行上传文件；上传动作写审计日志。

## 6. 家长只读分享

- 分享 token 使用 32 字节随机数（base64url），数据库中只保存 SHA-256 哈希，无法从数据库反推链接。
- 分享可设置 1–90 天有效期、可随时撤销；访问写入 `parent_share_access_log` 并累计访问次数，列表可见最近访问时间。
- 公开接口只返回该学生的成长报告，不含班级排名、其他学生、后台入口与完整学号；过期/撤销/不存在统一返回“分享链接无效或已过期”。
- `Cache-Control` 不缓存敏感页面（由 SPA 行为控制），公开数据仅用于家长查看。

**部署方必须完成**：通过学校已有家校渠道核验家长身份后再发放链接；链接只发给对应家长；学生毕业/转学或家长关系变更时及时撤销。能力 URL 一旦外泄即等同访问权，系统不提供二次身份验证（已知限制）。

## 7. 学生干部申报链接

- 班级级申报 token 同样只存 SHA-256 哈希，支持撤销/过期，记录使用次数与最近使用时间。
- 学生通过「学号 + 姓名」匹配校验身份，失败信息不区分“学号不存在”或“姓名不匹配”。
- 公开接口仅返回班级名称与分类列表，不返回学生名册；提交创建 `PENDING_REVIEW` 记录，不直接改变积分；按 IP 做频率限制。
- 申报内容与提交 IP 记录在数据库中，教师审核时可追溯。

## 8. 审计与备份

- 审计日志记录操作者、账号、角色、动作、目标对象、结果、IP、User-Agent、时间与变更摘要；审计日志表禁止更新/删除。
- 不记录密码、完整 token、密钥；公开接口的提交/访问只记录必要的 IP 与动作。
- 备份为真实 SQLite `VACUUM INTO` 快照，文件写入 `BACKUP_DIR`；备份任务状态来自真实执行结果，无伪造进度。
- 备份文件包含未成年人数据，必须限制文件权限并优先存放到受控位置；恢复流程见 [DEPLOYMENT.md](DEPLOYMENT.md)。

## 9. 隐私与教育伦理

- 系统只采集德育管理必需信息（学号、姓名、性别、班级、德育记录、证据、操作日志），不采集身份证号、照片、家庭住址等非必要信息。
- 系统不向学生/家长展示班级排名或其他学生信息；后台排名分析仅对授权教职工可见。
- 报表文案由确定性模板生成，使用客观、中性、建设性措辞，不标签化、不公开曝光；分数不用于自动决定奖学金、处分等重大事项。
- 申诉、更正与撤销均可追溯，学生/家长可通过学校渠道申请查询与更正。

## 10. 已知限制与部署方职责

- 家长身份核验依赖线下渠道（本版本无短信/统一身份认证）；建议后续接入学校统一认证或验证码。
- 系统未内置 HTTPS，必须由反向代理提供；纯 HTTP 部署时 Cookie 不具备 `Secure` 属性，仅建议用于隔离内网。
- 登录限流为单进程内存实现，多实例部署时需在网关层统一限流。
- SQLite 单文件数据库适合单校规模；多实例写入需改用 PostgreSQL。
- 本版本不含自动漏洞扫描与渗透测试，正式上线前建议按学校安全规范进行安全评估。

## 11. 安全事件响应建议

1. 立即停用相关账号（系统管理 → 账号状态），必要时更换 `APP_SECRET` 会使已加密敏感字段失效（见部署文档提示）。
2. 导出并保全审计日志（数据库只读副本）。
3. 撤销相关家长分享链接与申报链接。
4. 修复后通过冲正/更正流程处理受影响积分记录，保留完整审计链路。
5. 按学校与主管部门要求报告与通知。
